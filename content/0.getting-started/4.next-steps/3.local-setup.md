##

You have a project in the Cockpit and you are ready to build something. This guide walks you through setting up a local development environment so you can create and test a custom Laioutr app on your own machine.

::note
The words "app" and "module" are used interchangeably throughout Laioutr documentation. A Laioutr app **is** a Nuxt module.
::

## Prerequisites

Make sure you have these tools installed before you begin:

- [Node.js >= 22.12](https://nodejs.org/)
- [pnpm](https://pnpm.io/)
- [Laioutr CLI](/getting-started/next-steps/cli)
- A Laioutr project created in [the Cockpit](https://cockpit.laioutr.cloud)

## Setup

::steps

### Clone the App Starter

Grab the official [App Starter template](https://github.com/laioutr/app-starter) to get a pre-configured project structure with a playground, Laioutr registration, and conventions already in place.

```bash
npx giget@latest gh:laioutr/app-starter
cd laioutr-app-starter
```

You do not *have* to use the template, but it gives you a solid starting point. See the [App Starter](/apps/app-development/app-starter) docs for a full breakdown of the project structure.

### Connect to the Laioutr npm registry

Laioutr packages come from a private registry. The starter already maps the Laioutr scopes to it in `.npmrc.config`, so copy that into place:

```bash
cp .npmrc.config .npmrc
```

Then log in:

```bash
npm login --registry https://npm.laioutr.cloud
```

Approve the login in the browser. npm stores the token in your user `~/.npmrc`, so you only do this once per machine, not once per project. See [npm registry](/cockpit/project-settings/npm) for what the authorize screen asks for, how to verify the token, and how to authenticate CI instead.

### Install dependencies

```bash
pnpm install
```

### Fetch the project configuration

The **laioutrrc.json** file is a complete snapshot of your project's frontend configuration: pages, sections, field values, and app settings. It is generated from Studio and used for both local development and production builds.

Fetch it with the Laioutr CLI:

```bash
laioutr rc fetch -p <organization-slug>/<project-slug> -s <project-secret>
```

- Replace `<organization-slug>/<project-slug>` with your project identifier (e.g. `acme/storefront`).
- Replace `<project-secret>` with the project secret from [project settings](https://cockpit.laioutr.cloud/o/_/p/_/settings) in the Cockpit.

### Start the playground

The App Starter ships a playground that loads your module together with the project config you just fetched. Use it to develop sections and blocks. It also registers Laioutr DevTools, so you can inspect queries, actions, and resolvers from the same app.

```bash
pnpm dev
```

::

## Connect Studio to localhost

Once the playground is running, you can connect it to Laioutr Studio so that changes you make locally appear in the Studio preview. Studio field edits are also reflected in your local app.

::tip
Open [Studio](https://cockpit.laioutr.cloud/o/_/p/_/studio) for the same project you fetched the `laioutrrc.json` from. Press `Cmd+K` (macOS) or `Ctrl+K` (Windows/Linux) to open the command palette, then run **Developer: Use Localhost**. Studio will reload and connect to your local dev server.
::

::note
**Chrome users:** Chrome shows a permission dialog when a page tries to connect to localhost. Click **Allow** when prompted.

![Chrome Permission Dialog](/assets/img/chrome-local-network-access.png){width="400"}

More information is available [on the Chrome blog](https://developer.chrome.com/blog/local-network-access).
::

::warning
When you add new sections or blocks, you need to restart the playground **and** reload Studio to pick them up. For changes to fields on existing sections or blocks, open the command palette and run **Developer: Reload Client Context** (or refresh the page). Schema-level changes always require a dev server restart.
::

## Development

With your environment running, you are ready to build. The most important difference between a regular Nuxt module and a Laioutr app is the `registerLaioutrApp` call in your `module.ts` file. This is how you register Laioutr-specific functionality.

### Adding UI sections and blocks

Register section and block directories in your `module.ts`:

```ts
await registerLaioutrApp({
  /** ... */
  sections: [resolve('runtime/app/sections')],
  blocks: [resolve('runtime/app/blocks')],
});
```

This scans and registers all section and block Vue files in those folders. Each component needs a `definition` export so Studio and Frontend Core know how to render and configure it. See [App Configuration](/apps/app-development/app-configuration) for details on definitions and config keys.

### Adding Orchestr integrations

**Orchestr** integrations let you connect external services (commerce, CMS, search) to your frontend through a unified API layer.

Register your Orchestr directory in `module.ts`:

```ts
await registerLaioutrApp({
  /** ... */
  orchestrDirs: [resolve('runtime/server/orchestr')],
});
```

This watches the Orchestr folder for changes and automatically restarts the server when a file is modified.

## Troubleshooting

### `ERR_PNPM_FETCH_403`

pnpm cannot authenticate with the Laioutr package registry. Your token is missing, expired, or bound to the wrong organization. Run `npm whoami --registry https://npm.laioutr.cloud` to see which credential npm is reading, then `npm login --registry https://npm.laioutr.cloud` to renew it. See [npm registry](/cockpit/project-settings/npm) for details.

### `unexpected end of JSON input`

Your `laioutrrc.json` file is corrupted or incomplete. Delete it and re-fetch:

```bash
rm laioutrrc.json
laioutr rc fetch -p <organization-slug>/<project-slug> -s <project-secret>
```

### `command not found: laioutr`

The Laioutr CLI is not installed. Install it globally:

```bash
pnpm add -g @laioutr/cli@latest
```

See the [CLI documentation](/getting-started/next-steps/cli) for more details.

### Dev server won't start

Check your Node.js version. Laioutr requires **Node.js >= 22.12**:

```bash
node --version
```

If you are on an older version, update Node.js before trying again. Also make sure you have run `pnpm install` successfully (no errors in the output) before starting the dev server.
