## Operations Center

The **Operations Center** is where your organization's agents work on a project. An agent measures the environment's live storefront or content, explains what is off, and records what it found. Where it proposes a change, a person approves it before anything is written. Every run is started by a person and paid in [credits](/larry-ai/ai-credits); nothing runs on a schedule.

Open **Operations Center** from the project sidebar, after Studio. It always shows the environment you are in.

[Open the Operations Center in the Cockpit](https://cockpit.laioutr.cloud/o/_/p/_/operationcenter)

### The agents

Three agents are there in every project's Operations Center from the start: nobody adds them. Having them costs nothing, because they never run by themselves; each run is started by a person and paid in credits.

| Agent | What it does | What it measures (signals) | Most one run costs |
| --- | --- | --- | --- |
| **Performance agent** | Measures the environment's live pages with Google PageSpeed Insights, mobile and desktop: Lighthouse lab data and, where Google has enough, the Core Web Vitals of real visitors. Reports what slows the pages down | Largest Contentful Paint (LCP), Interaction to Next Paint (INP), Cumulative Layout Shift (CLS), Time to First Byte (TTFB), Lighthouse score mobile and desktop; each for the home, category and product page | 20 credits |
| **SEO agent** | Reads the environment's sitemap, checks an evenly spread sample of its live pages for 404s, `noindex`, a canonical pointing elsewhere, hreflang, titles, meta descriptions and structured data, and reports what to fix | Share of sampled pages with structured data and with a Meta Description; sampled pages answering 404, indexable, with hreflang problems, sharing a title | 20 credits |
| **Content agent** | Reviews the project's content entries: drafts that do not validate, entries never published, published entries with unpublished changes | Content entries, drafts that do not validate, entries never published, published entries with unpublished changes | 10 credits |

Notes on what they read:

- The **Performance agent** measures the home page of the first active market's default domain, a category and a product page where their paths are known, and the home page of every other active market. Its charts follow the first market.
- The **SEO agent** reads `/sitemap.xml` of the first active market's default domain and audits a sample of up to 20 pages. Its counts are of that sample, not of the whole site.
- The **Content agent** reviews the project's content, which every environment of the project shares. Its counts are recorded only when every entry was read. What it found is shown only to people who may edit content.

To protect your storefront, the Performance and SEO agents measure each environment at most **4 times an hour** (one every 15 minutes) and **12 times a day** by default; a larger license can allow more. The Performance agent also shares Google's quota with every customer. When a measurement is held back, the page says until when.

### Before the first run

Until an agent has run in this environment, its cards show **—** and **Not measured**, with their target where one is set. The banner at the top points to the first measurement: **Measure now** runs every agent of the project after you confirm the estimate.

Cards of the design that no agent measures yet, such as the Commerce group of a conversion agent, are shown with their example values and marked **EXAMPLE**, so you see what is coming. Only cards without that mark are your data. Where such an agent is not available yet, **Request** tells the Laioutr team you want it; nothing is charged.

### Other agents

Agents beyond the three are added with **Add agent** in the header or from the **Marketplace**. A project has one agent of each kind. Such an agent joins your organization's agent library and starts as a **draft**:

1. **Run test** runs it once as it is set up. The estimate is shown first and the test is paid in credits. A test's proposed changes can be rejected, never approved.
2. **Activate** once the test passed. From then on, everyone who sees agents can start it.

Each agent links to its **set-up page**: its name, instructions, projects, tools (read, draft, apply) and skills, its credit limit per run and per month, and the model it runs on. Changing the instructions, projects, tools or skills of an added agent returns it to draft: it needs a new test run before it runs again. A new name or new credit limits do not.

From an agent's **⋯** menu an Owner can **Pause** it (a run it has open ends; what it found stays) or **Remove** it (it leaves the library and runs no more; its history stays).

### Running agents

- **Run analysis** opens a confirmation with the estimated credits: the median of the agent's last runs, or its run limit, which a run never goes past, while it has not run yet. Only **Run analysis** in the confirmation starts it. The organization's credits pay: plan credits first, then purchased credits.
- **Measure now** above the cards lists every agent of the project with its estimate, or why it is left out (not active, a run already open, a measurement held back, the license, your access, or credits the balance or a limit cannot cover), and the total. Confirming starts the agents listed as starting.
- While an agent runs, the page shows **Running...** and updates by itself.

How a run is paid, and what happens when the balance or a limit cannot cover it, is explained under [How an agent run is paid](/larry-ai/ai-credits#how-an-agent-run-is-paid).

### The tabs

| Tab | What it shows |
| --- | --- |
| **Signals** | One group per agent with a card per signal, drawn from what its runs measured in this environment. A signal not measured yet is an empty frame that says what to do |
| **Findings** | What the agents found. A finding opens its report: the pages, what was measured or found, the threshold or suggested change, why it matters and what usually causes it |
| **Actions** | Changes the agents propose, each with **Approve** and **Reject** |
| **History** | Every run in this environment: agent, status, who started it, credits and when |

On a finding:

- **Dismiss** marks it as not relevant.
- **Fix** starts a run of an agent that can fix that kind of finding, after showing its estimate. Its proposals appear under **Actions**, and nothing changes until a person approves each one. Where no agent can fix it yet, **Fix** is greyed and says why, with the way on: get the agent, add it, open its set-up, or **Request** it from the Laioutr team (nothing is charged).

**Approving a change** runs it as the person approving, with their own access. Where a proposed change holds a hidden email address, the card asks you to type it. When a run proposes changes, everyone who may see agents is told through the Cockpit's notifications.

Findings, proposed changes and measured values that need access you do not hold are hidden from you; the tab says how many.

### When nothing was measured

When an agent's latest run measured nothing, its group says why above its cards:

| Agent | Message | What to do |
| --- | --- | --- |
| Performance | Page speed measuring is not set up on the platform yet | Ask support to set it up |
| Performance, SEO | No active market of this environment has a domain | Give a market a domain, then run the agent again |
| SEO | The storefront answers no sitemap at `/sitemap.xml` | Publish a sitemap there, then run the agent again |
| Content | Content editing is not on for this project | Run the agent again once it is on |

### Who may do what

| Who | Can |
| --- | --- |
| Content Manager and above in the organization | Open the Operations Center and see agents, start an active agent, approve or reject proposed changes, dismiss findings |
| Owners | Everything above, add agents and change their set-up, run tests, activate, pause and remove agents, set credit limits |
| Developers, Project Managers, Content Managers | Add agents, change their set-up, run tests and activate them too, where the Owners allow it in the organization's **Settings -> Agents -> Who may add and change agents** |

Pausing and removing agents and their credit limits stay with the Owners. Approving a change also needs the access the change itself needs. Someone with a role only on a project or an environment sees the Operations Center without its agents and is asked to request access from an Owner.

### Notifications

The Owners are told when a run of an agent was reset (the balance or a credit limit did not cover it), when an agent reached its credit limit, and when a run failed. Everyone who may see agents is told when an agent's changes wait for approval.
