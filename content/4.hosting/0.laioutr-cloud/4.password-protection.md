Password protection puts a password page in front of a hostname of your storefront. The check runs at Cloudflare's
edge, before the request reaches your storefront or its cache. The [limits](/hosting/laioutr-cloud/limits#password-protection)
page lists its numbers.

## What it protects

- **Previews** are protected by default: every deployment's own address (`<name>-<9 characters>.laioutr.app`) and the
  addresses of environments other than production.
- **Production's own hostname and your domains** are protected when you switch them on, one by one.
- **An apex hostname** (`example.com` without `www`) is never protected. It redirects to `www`; protect that hostname.

When you protect one hostname of a storefront while another hostname serves the same storefront publicly, Cockpit
names the public one, so the content is not reachable unprotected by accident.

## What stays reachable

A path with a segment after `/webhooks/`, such as `/webhooks/app-<name>/<webhook>`, stays reachable without the
password on every protected hostname. A service that sends webhooks from its own servers cannot enter a password; it
signs each delivery instead. The edge does not check that signature. The route under `/webhooks/` has to, before it
parses the delivery or acts on it, so whatever a route there answers, it answers to anyone. The edge passes these
requests on with their method, headers and body unchanged. It only takes the protection's own header, query
parameters and cookie off the request, the referer included, and resolves `.` and `..` segments in the path.

Nothing else is exempt. Every other path an app serves, its OAuth callbacks included, stays behind the password.
`/webhooks` and `/webhooks/` themselves are protected, and so is a path that only resembles a delivery path: one that
leaves the prefix once resolved, such as `/webhooks/../checkout`, one with an empty segment right after the prefix,
such as `/webhooks//x`, and one with an encoded `/`, `\` or `.` (`%2F`, `%5C`, `%2E`, in either case) anywhere in its
path.

::warning
**A deployment built with a Frontend Core release older than the one that reserves `/webhooks/` shows a page under
`/webhooks/` to anyone, without the password.** From that release on, Frontend Core answers a path under `/webhooks/`
that no route claims with a plain 404, and no longer serves a Studio page there. An older build renders such a path
like any other page: usually the storefront's own 404 page with its header, footer and navigation, or the Studio page
at that path if there is one. Upgrade Frontend Core to the latest release on each protected storefront and deploy it.
A deployment built before the upgrade keeps this behavior on its own address for as long as it is
[kept](/hosting/laioutr-cloud/limits#preview-deployments): a preview until a newer deployment of its name replaces it,
a replaced production deployment for 24 hours. Rolling production back to such a deployment brings it back on your
hostnames.
::

## Setting the password

Open [Hosting › Laioutr Cloud](https://cockpit.laioutr.cloud/o/_/p/_/hosting/laioutr-cloud) in Cockpit and go to
**Password protection**. Project Managers and Owners can set it.

A project has one password. A new password replaces the old one and logs out everyone who used the old one. A
visitor who entered the password stays logged in for 7 days.

## Bypass secrets for automation

A bypass secret lets a machine through without the password page: a CI smoke test, an end-to-end test suite, a
monitoring check. Create one per machine in the same panel, so you can revoke one without the others.

- Send the secret in the header `x-laioutr-protection-bypass: <secret>`.
- When you cannot set a header, send it as the query parameter `?x-laioutr-protection-bypass=<secret>`.
- To get a cookie instead, add `x-laioutr-set-bypass-cookie=true` to a `GET` request with the secret. The answer
  sets the cookie and redirects to the same URL without the parameters. Inside a cross-site frame, use
  `x-laioutr-set-bypass-cookie=samesitenone`.

A wrong secret is treated like none: the visitor sees the password page. The secret never reaches your storefront.
A revoked secret stops working within 60 seconds.

## Laioutr Studio

Laioutr Studio has its own bypass secret, which Cockpit creates for you. It lets Studio show your protected previews.
It cannot be revoked; if it leaks, rotate it in the panel.

::note
**In Safari, Studio shows the password page for a protected hostname.** Safari blocks every cookie inside a
cross-site frame, partitioned cookies included, so the cookie Studio's secret sets never reaches the frame. Use
Chrome, Edge or Firefox for Studio on a protected hostname, or switch protection off for that hostname while you edit.
::

## Examples

A CI smoke test against a deployment's own address:

```bash
curl -fsS -H 'x-laioutr-protection-bypass: prbp_…' https://<name>-<9 characters>.laioutr.app/
```

A Playwright suite that sends the secret with every request:

```ts [playwright.config.ts]
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    baseURL: process.env.PREVIEW_URL,
    extraHTTPHeaders: { 'x-laioutr-protection-bypass': process.env.LAIOUTR_PROTECTION_BYPASS! },
  },
});
```
